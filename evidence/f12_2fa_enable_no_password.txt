F12 — 2FA dapat diaktifkan tanpa konfirmasi password (assurance downgrade / account takeover persisten)
Target   : https://diksy.ilkom.unej.ac.id
Tanggal  : 2026-10-27
Metode   : sesi terautentikasi milik penguji sendiri; akun uji @unej.ac.id sekali pakai.
           Tidak ada kredensial pihak ketiga yang dipakai, tidak ada data pengguna lain
           yang dibaca. Nilai rahasia (cookie, token CSRF, seed TOTP, password) disamarkan.

KELAS SERANGAN
  Cloudflare security-audit -> WEB-PROTOCOL-AND-AUTH.md
  "MFA enrollment and assurance downgrade": enrollment/replacement second factor harus
  menuntut assurance sebelumnya (fresh auth / password), bukan hanya sesi.

A. ASIMETRI FORM (bukti struktur)

  GET /profile/2fa/setup   -> form POST /profile/2fa/enable
       fields: _csrf, code
  GET /profile (saat aktif) -> form POST /profile/2fa/disable
       fields: _csrf, password, code

  Perintah:
    curl -s -b "BLSESSID=[REDACTED]" https://diksy.ilkom.unej.ac.id/profile/2fa/setup \
      | grep -o '<form[^>]*action="[^"]*"\|name="_csrf"\|name="code"\|name="password"'
    -> action="/profile/2fa/enable", name="_csrf", name="code"
       (tidak ada name="password" di form ini)

B. ENABLE TANPA PASSWORD (bukti perilaku)

  POST /profile/2fa/enable
    data: _csrf=<token sesi>, code=<6 digit dari seed yang ditampilkan halaman setup>
    -> 302  Location: /profile

  GET /profile sesudahnya merender form "Nonaktifkan 2FA" + action="/profile/2fa/backup-codes".
  Sebelum request itu, /profile merender "Aktifkan 2FA".

  Artinya: dua field (CSRF + kode TOTP) sudah cukup untuk menulis totp_enabled=1.
  Tidak ada field password, tidak ada step-up, tidak ada re-autentikasi.

C. PEMBANDING DENGAN FRAMEWORK ASLI (sumber bFramework)

  src/app/core/Auth/LocalDriver.php
    twofaBegin()    -> $this->verifyPassword($acc, $r->post['password'])  sebelum begin()
    twofaConfirm()  -> verifyPassword() lagi; komentar sumber: "S4: secret tertunda hanya
                       ditampilkan setelah password valid"
    twofaDisable()  -> verifyPassword() + twofa->verifyLogin() (kode lama wajib)

  bLecturer mempertahankan syarat password pada disable, tetapi tidak pada enable.
  Konsekuensinya bukan "fitur hilang", melainkan kontrol yang hanya dijaga satu arah.

D. DAMPAK (rantai, bukan teori)

  1. Penyerang memegang cookie BLSESSID (XSS di origin yang sama, perangkat bersama,
     cookie tanpa __Host- prefix, atau sesi yang tidak dirotasi).
  2. POST /profile/2fa/enable dengan seed milik penyerang -> 2FA penyerang aktif.
  3. Pemilik akun login dengan password benar -> server mengarahkan ke /login/2fa
     (terverifikasi: 302 /login/2fa, bukan /dashboard).
  4. Pemilik tidak dapat mematikan 2FA: form disable menuntut password + kode TOTP
     yang hanya penyerang punya.
  -> Pengambilalihan permanen dari satu cookie sesi, tanpa pernah mengetahui password.

E. APA YANG TIDAK TERBUKTI

  - Tidak diuji: apakah enable juga menerima permintaan lintas-situs (CSRF murni).
    Form membawa _csrf, dan percobaan tanpa token menghasilkan 500 (lihat F3/F10),
    jadi jalur lintas-situs tanpa membaca token tidak terbukti.
  - Tidak diuji: rotasi secret saat /profile/2fa/setup dipanggil ulang pada akun yang
    2FA-nya sudah aktif (akun uji tidak lolos gerbang /email/verify).
  - Tidak diklaim: bypass 2FA saat login. Login benar-benar menuntut kode.

F. REPRODUKSI AMAN (tanpa menyentuh akun siapa pun)

  Butuh satu sesi milik sendiri pada akun yang email-nya sudah terverifikasi.
    1) GET  /profile/2fa/setup          -> salin token _csrf dan seed Base32
    2) hitung TOTP 6 digit dari seed (RFC 6238, 30 detik, SHA1)
    3) POST /profile/2fa/enable         -> _csrf, code      [tanpa password]
    4) GET  /profile                    -> harus muncul "Nonaktifkan 2FA"
    5) pulihkan: POST /profile/2fa/disable dengan _csrf, password, code
       (kode harus dari window 30 detik BERIKUTNYA; kode yang sudah dipakai login
        ditolak oleh anti-replay totp_last_step)

G. PERBAIKAN MINIMAL

  Di handler enable: wajibkan password (atau fresh re-auth) sebelum setSecret/enable,
  sama seperti twofaBegin/twofaConfirm di framework. Satu guard di titik tulis,
  bukan di view. Tambahkan juga rotasi sesi setelah 2FA berubah.
