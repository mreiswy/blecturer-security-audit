# F8 — Registrasi menerima password 8 karakter & password umum
# target : https://diksy.ilkom.unej.ac.id
# tanggal: 2026-10-27
# akun   : sekali pakai (qa*@mail.unej.ac.id), tidak diverifikasi, tidak dipakai lagi
# rahasia: tidak ada cookie/token/nilai password yang disimpan di berkas ini

## 1. Form registrasi menyatakan batas 8, bukan 10

$ curl -s https://diksy.ilkom.unej.ac.id/register | grep -oE 'name="password"|minlength="[0-9]+"|maxlength="[0-9]+"'
name="password"
minlength="8"
maxlength="100"

Atribut `minlength` hanya petunjuk sisi klien. Yang menentukan adalah validasi server.

## 2. Server menerima 8 karakter, termasuk sandi yang ada di daftar-larang framework

Setiap baris memakai email baru, NIM baru, dan cookie jar baru.
`302 /email/verify` = registrasi DITERIMA (akun dibuat, menunggu verifikasi email).
`302 /register` = ditolak (hanya terjadi untuk panjang 3–5).

$ pw='password';   POST /register  ->  HTTP 302  Location: /email/verify
$ pw='abcdefgh';   POST /register  ->  HTTP 302  Location: /email/verify
$ pw='12345678';   POST /register  ->  HTTP 302  Location: /email/verify
$ pw='abcde';      POST /register  ->  HTTP 302  Location: /register      (ditolak: 5 karakter)
$ pw='abc';        POST /register  ->  HTTP 302  Location: /register      (ditolak: 3 karakter)

Batas bawah di server karenanya 8 karakter (6–7 tidak dapat diuji ulang: kuota
registrasi per-IP 429, lihat catatan metodologi).

        ...
        $len = mb_strlen($password);
        if ($len < self::MIN_LENGTH) {
            $errors[] = 'Password minimal ' . self::MIN_LENGTH . ' karakter.';

`'password'` dan `'12345678'` ada di `COMMON`; keduanya lolos di target.
`PasswordPolicy::check()` juga memakai `$email` (menolak sandi yang memuat
email/NIM), sementara di target parameter itu tidak berpengaruh.

## 4. Mengapa ini berdampak, bukan sekadar "kebijakan lemah"

- Akun memakai email kampus yang **tidak bisa diganti** dan NIM yang menjadi
  identitas akademik. Password lemah di sini bukan risiko akun sekali pakai.
- Registrasi menerima akun sebelum email diverifikasi (F8), jadi sandi lemah
  sudah tersimpan sebelum pemilik membuktikan apa pun.
- Tidak ada alur reset password (F8): korban tidak punya jalan pulih selain
  lewat admin.
- Tidak ada 2FA wajib, dan 2FA justru bisa dipasang pihak lain (F12).
- Kombinasi F13 + F6 (enumerasi email/NIM) + F11 (kuota ~10/menit/IP) membuat
  credential stuffing murah: sandi umum di daftar-larang framework adalah
  tebakan pertama yang wajar.

## 5. Batasan pengujian (jujur)

- Tidak ada percobaan login ke akun orang lain; hanya registrasi akun baru
  milik penguji.
- 6–7 karakter tidak dapat dipastikan: kuota registrasi per-IP (429) menutup
  bucket sebelum uji selesai. Yang terbukti adalah 8 diterima dan 5 ditolak.
- `password_confirmation` diuji selalu sama; perilaku saat berbeda tidak diuji.
- Batas bawah 8 adalah **nilai deployment**, bukan nilai framework. Ini
  konsisten dengan pola F12: lapisan validasi framework dilepas di deployment.
